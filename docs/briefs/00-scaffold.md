# Brief 00 — `chore: scaffold + framework contract`

**Mode:** Greenfield scaffold. This is the approved exception for manifests, the lockfile and workflows.
**Jira:** SC-2
**Read first:** `docs/PLAN.md` (whole file), especially "Visual design: CodeRabbit brand" and PR 0.

## Goal

Give the repo an empty but working Next.js app, CI, and the review and pipeline setup that every later PR depends on. No storefront features yet.

## Deliverables

1. **App skeleton**
   - `package.json` named `deskdrop`, `"type": "module"`, engines `node >=22.6.0`. Dependencies exactly: `next ^16.4.3`, `react ^19.3.1`, `react-dom ^19.3.1`, `lucide-react ^1.63.0`. devDependencies exactly: `@playwright/test ^1.64.1`, `@types/node ^26.6.5`, `@types/react ^19.3.0`, `@types/react-dom ^19.3.0`, `typescript ^7.0.2`. Nothing else.
   - Scripts: `dev`, `build`, `start` (all with `--hostname 0.0.0.0`), `typecheck` (`tsc --noEmit`), `test` (`node --experimental-strip-types --test tests/*.test.mjs`), `test:e2e` (`npm run build && playwright test`), `golden:check` (exits 0 with "no goldens yet" until PR 2).
   - `package-lock.json` generated by `npm install`.
   - `tsconfig.json`, `next.config.ts`, `next-env.d.ts`, `.gitignore` (node_modules, .next, test-results, playwright-report, artifacts).
   - `app/layout.tsx` and `app/page.tsx`: a minimal page with the heading "DeskDrop". No styling or fonts yet; those come in PR 3.
   - `tests/smoke.test.mjs`: one real assertion. For example, `package.json` declares exactly the dependencies above, so the test fails if a dependency is added.

2. **CI** — `.github/workflows/ci.yml`, on `pull_request` and `push` to `main`, with no path filters.
   - Parallel jobs: `typecheck`, `unit` (`npm test`), `golden` (`npm run golden:check`).
   - Node 22, `npm ci`, npm cache. Each job should finish in a few minutes.

3. **`.coderabbit.yaml`**
   - `reviews.request_changes_workflow: true`.
   - Path instruction for `tests/golden/**`: any golden change in a PR whose title starts with `refactor` is Critical. In a `fix` or `feat` PR, the golden diff must match the PR description.
   - Path instruction for `app/**/*.css` and `components/**`: a raw hex or rgb color outside the `:root` token block in `app/globals.css` is a Major finding (see `docs/BRAND.md`).
   - `tools`: gitleaks and semgrep enabled. Disable eslint, since CI runs typecheck instead and there is no eslint config.
   - `pre_merge_checks.custom_checks`: "Security Gate", `mode: error`, using the instruction text from the framework (fail only on security-related Major or Critical issues).
   - `knowledge_base.code_guidelines.filePatterns`: `**/AGENTS.md` and `docs/BRAND.md`.

4. **`AGENTS.md`** — the author rules:
   - the stack;
   - no new dependencies without an approved `ALLOW:` line;
   - a test for each new behavior, asserting behavior rather than imports;
   - the cart rules in `docs/PLAN.md` are requirements;
   - no TODOs, debug prints or reasoning comments;
   - never edit goldens unless the brief allows it;
   - follow `docs/BRAND.md`.

5. **`docs/BRAND.md`** — the "Visual design: CodeRabbit brand" rules from `docs/PLAN.md`, written as a review checklist. Include:
   - the token names that PR 3 will define: `--color-primary`, `--color-accent-mint`, `--color-accent-cobalt`, `--color-bg`, `--color-surface`, `--color-text`, `--color-muted`, `--color-border`;
   - the logo rules, with the footer credit as the only CodeRabbit mark.

6. **Pipeline scripts** in `scripts/golden/`: POSIX bash, `set -euo pipefail`, no new dependencies, each with `--help`.
   - `scope-gate.sh <base> <head> [allow-file]`: fails when the diff touches `package.json`, `package-lock.json`, `.github/**` or `tests/golden/**` unless an `ALLOW:` glob in the allow file covers it. When an allow file is given, every changed file must match one of its globs.
   - `red-green.sh <base> <head> <test-file>...`: runs the named tests on a temporary worktree of base (they must fail) and of head (they must pass).
   - `strict-gate.sh <pr-number>`: uses `gh` to require all of the following, and prints the reasons for any failure:
     - CodeRabbit approval;
     - zero unresolved review threads;
     - no "Critical" or "Major" in the latest CodeRabbit review body;
     - every check on the head commit successful, including `CodeRabbit Security` and the Security Gate.
   - `judges/preamble.md` plus `judges/scope.md`, `judges/behavior.md`, `judges/tests.md` and `judges/security.md`: one narrow, read-only brief per judge, from section 6 of the framework as summarized in `docs/PLAN.md`. Each judge ends with `VERDICT: PASS` or `VERDICT: FAIL` and its reasons.
   - `tests/scripts.test.mjs`: unit tests for `scope-gate.sh` using a temporary git repo. One test makes a denied change and expects failure; one makes a change allowed by an `ALLOW:` glob and expects success.

7. **`docs/stage-log.csv`** with the header `pr,stage,start_utc,end_utc,notes`.
