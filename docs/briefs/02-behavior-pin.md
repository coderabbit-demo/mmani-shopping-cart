# Brief 02 — `feat: behavior pin for domain`

**Mode:** pin the accepted feature. The goldens are new: no existing golden changes, because none exist yet. **Jira:** SC-5
**Read first:** `docs/PLAN.md`, sections 5.1 and PR 2, and `AGENTS.md`.

## Assumptions (verified 2026-10-28 on main 861121b)

- `package.json` has `"golden:check": "node -e \"console.log('no goldens yet')\""`. CI's `golden` job (`.github/workflows/ci.yml:36-46`) runs `npm run golden:check` on every PR and push to `main`, so no workflow change is needed.
- `scope-gate.sh` protects `package.json` and `tests/golden/*`. They pass only with explicit `ALLOW:` lines, which this brief gives.
- `.coderabbit.yaml` has a path instruction for `tests/golden/**`: in a `feat` PR, every golden difference must match the PR description. This PR adds goldens only.
- `lib/store.ts` exports `initialState`, `addItem`, `changeQuantity`, `removeItem`, `lineTotal`, `subtotal`, `applyCoupon`, `removeCoupon`, `setDelivery`, `totals`, `signIn`, `signOut`, `toggleWishlist` and `placeOrder`. `lib/catalog.ts` exports `categories`, `products`, `productById` and `money`. All are pure; `placeOrder` takes `id` and `createdAt` explicitly, so captures are deterministic.
- Node scripts that import `lib/*.ts` need `--experimental-strip-types`, as `npm test` already uses on Node 22 (CI) and 24 (local).

## Goal

Every user-visible output of the cart logic is pinned byte for byte, so any later PR that changes behavior shows up as a golden diff its brief must name.

## Deliverables

1. **`scripts/golden/scenarios.mjs`** exports an ordered array of named, deterministic scenarios. Each is `{ name, run }`, where `run()` calls `lib/` functions and returns a plain JSON-safe object of outputs: states, `totals()`, errors, notices and formatted money. Errors are captured as `{ error: { name, message } }`. Scenarios to include, at least:
   - `catalog`: every product's id, name, price, `money(price)`, category, color names and inStock, plus `categories`;
   - `money-format`: `money` of 0, 24.3, 68, 100.1 and 137.7;
   - `empty-cart`: totals of `initialState`;
   - `rule1-two-colors`, `rule1-merge-same-color`, `rule1-invalid-color`;
   - `rule2-quantity-change`, `rule2-clamp`, `rule2-invalid-quantity`;
   - `rule3-desk15-162` (lamp + keyboard), `rule3-recompute-on-add`, `rule3-removed-below-100` (with the notice), `rule3-exactly-100` (lamp + organizer), `rule3-invalid-codes`;
   - `rule4-express`, `rule4-express-with-coupon`;
   - `rule5-signin-keeps-wishlist`, `rule5-wrong-credentials`;
   - `rule6-three-line-order`, with fixed id `"DD-GOLDEN1"` and createdAt `"2026-10-28T12:00:00.000Z"`;
   - `cents-100-10`: a synthetic `{ ...products[0], price: 100.10 }` with DESK15, standard and express.

2. **`scripts/golden/capture.mjs`**:
   - **Capture mode** (`node --experimental-strip-types scripts/golden/capture.mjs`):
     - writes one file per scenario, `tests/golden/domain/<name>.json`, using `JSON.stringify(value, null, 2) + "\n"`;
     - writes `tests/golden/MANIFEST.sha256`, with lines `<sha256>  domain/<name>.json` sorted by path;
     - writes `tests/golden/BASELINE`: the 40-hex SHA from `git rev-parse HEAD` at capture time, then a newline.
   - **Check mode** (`--check`) writes nothing and exits nonzero with a reason on any of:
     - a scenario's fresh output differs byte for byte from its golden;
     - a golden file is missing, or an extra file exists under `tests/golden/domain/`;
     - `MANIFEST.sha256` doesn't match the golden files' hashes;
     - `BASELINE` is missing or isn't 40 hex characters.

     It prints `PASS: <n> goldens match` on success. It must fail closed: no path exits 0 without printing PASS.
   - `--help`.

3. **`package.json` scripts:**
   - `"golden:check": "node --experimental-strip-types scripts/golden/capture.mjs --check"`;
   - `"golden:capture": "node --experimental-strip-types scripts/golden/capture.mjs"`, the one-command refresh from framework section 5.10.

   No other change to `package.json`. No dependency changes.

4. **`tests/golden/`:** the captured goldens, `MANIFEST.sha256` and `BASELINE`, generated by running `npm run golden:capture` and never hand-edited.

5. **`tests/golden.test.mjs`**, run by `npm test`. Each test works on a temporary copy of `tests/golden` and the scripts, never the real files. It covers:
   - check passes on the committed goldens;
   - a one-byte change to a golden → fails, naming the file;
   - a missing golden → fails;
   - an extra file in `domain/` → fails;
   - a manifest hash mismatch → fails;
   - a missing or malformed `BASELINE` → fails;
   - capture then check on a clean copy → passes, and running capture twice is byte-identical, so it's deterministic;
   - a planted behavior change produces a golden mismatch, naming the scenario. For example, run check with a copy of `lib/store.ts` where express shipping is 13.

   Each test asserts the exit code and the output.

**Red-then-green:** brand-new scripts and goldens, so not applicable for the new test file. The tests judge proves the tests. `npm run golden:check` going from the placeholder to real checks is the behavior change in this PR.
